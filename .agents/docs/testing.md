# Testing Guide — provider-upjet-aws

## Overview

This repository uses three testing layers:

| Layer | What it validates | Where it runs |
|-------|-------------------|---------------|
| **Unit tests** | Config converters, client utilities, password generators | `go test` locally or CI |
| **Integration (local deploy)** | Provider builds, loads into Kind, reaches `Healthy` | CI (`make local-deploy`) |
| **E2E (Uptest)** | Full resource lifecycle against real AWS | CI via PR comment or locally |

Unit test coverage is minimal — 8 test files total, all hand-written around config converters and client utilities. Controllers are entirely generated by Upjet and have no unit tests. **E2E via the Uptest framework is the primary quality gate.**

### Running Unit Tests

```bash
# Run all unit tests (parallelism defaults to NPROCS/2)
make test

# Run only config tests
go test ./config/...

# Run only client tests
go test ./internal/clients/...

# Generate Cobertura coverage report (filters out zz_ generated files)
make cobertura
```

The `cobertura` target reads `coverage.txt`, strips all lines matching `zz_` (auto-generated code), and writes `cobertura-coverage.xml`. In CI, unit tests run as `make -j2 test`.

### Test Patterns

All tests follow standard Go conventions:

- **Table-driven tests** with named cases in `map[string]struct{ args; want }{}`.
- **Subtests** via `t.Run(name, func(t *testing.T) { ... })`.
- **`google/go-cmp`** for structural comparison — diffs printed on failure with `cmp.Diff()`.
- **`crossplane-runtime/v2/pkg/test`** for mock Kubernetes clients (`test.MockClient`) and error comparison helpers (`test.EquateErrors()`).
- **`crossplane/upjet/v2/pkg/resource/fake`** for mock Terraformed resources.
- **`crossplane-runtime/v2/pkg/resource/fake`** for mock Managed resources.

Example pattern (from `config/cluster/autoscaling/config_test.go`):

```go
func TestAutoScalingGroupConverterFromv1beta1Tov1beta2(t *testing.T) {
    type args struct {
        src    *v1beta1.AutoscalingGroup
        target *v1beta2.AutoscalingGroup
    }
    type want struct {
        target *v1beta2.AutoscalingGroup
        err    error
    }
    cases := map[string]struct {
        args args
        want want
    }{
        "Successful": {
            args: args{src: &v1beta1.AutoscalingGroup{...}, target: &v1beta2.AutoscalingGroup{}},
            want: want{target: &v1beta2.AutoscalingGroup{...}, err: nil},
        },
        "Unsuccessful": { /* ... */ },
    }
    for name, tc := range cases {
        t.Run(name, func(t *testing.T) {
            err := autoScalingGroupConverterFromv1beta1Tov1beta2(tc.args.src, tc.args.target)
            if diff := cmp.Diff(tc.want.err, err, test.EquateErrors()); diff != "" {
                t.Errorf("...: -want error, +got error:\n%s", diff)
            }
            if diff := cmp.Diff(tc.want.target, tc.args.target); diff != "" {
                t.Errorf("...: -want target, +got target:\n%s", diff)
            }
        })
    }
}
```

## E2E Tests (Uptest Framework)

Uptest is the primary testing mechanism. It validates the full resource lifecycle — create, observe, update, import, delete — against a real AWS account through a Kind-hosted Crossplane control plane.

### Key Versions

| Tool | Version |
|------|---------|
| Uptest | v2.2.0 |
| Kind | v0.30.0 |
| Crossplane | 2.2.0 |
| Kustomize | v5.3.0 |

### Example Manifests as Test Fixtures

Example YAML manifests serve as both documentation and E2E test input:

```
examples/                    # ~2,332 hand-written manifests
├── {service}/
│   ├── cluster/
│   │   └── v1beta1/
│   │       └── {resource}.yaml
│   └── namespaced/
│       └── v1beta1/
│           └── {resource}.yaml

examples-generated/          # ~2,011 auto-generated from Terraform docs
├── {service}/
│   └── ...
```

Each manifest is a complete Crossplane resource that Uptest can apply, wait for readiness, and then delete.

### Running E2E Tests

#### Via CI (PR comment trigger)

```
/test-examples="examples/s3/cluster/v1beta1/bucket.yaml"
```

#### Locally

```bash
# Test a single resource
make uptest UPTEST_EXAMPLE_LIST="examples/s3/cluster/v1beta1/bucket.yaml"

# Full family test — builds only the needed sub-packages, deploys to Kind, runs uptest
make e2e \
  UPTEST_EXAMPLE_LIST="examples/s3/cluster/v1beta1/bucket.yaml" \
  UPTEST_CLOUD_CREDENTIALS="$(cat creds.txt)"

# Alias: make family-e2e (identical to make e2e)

# ProviderConfig auth method tests against EKS
make providerconfig-e2e
```

### Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `UPTEST_CLOUD_CREDENTIALS` | For E2E | AWS credentials as key=value pairs. Supports `DEFAULT` and `PEER` keys (creates `default` and `peer` ProviderConfigs). |
| `UPTEST_EXAMPLE_LIST` | For E2E | Comma-separated paths to example YAML manifests to test. |
| `UPTEST_DATASOURCE_PATH` | Optional | Path to datasource YAML (conventionally `.work/uptest-datasource.yaml`) for injecting dynamic runtime values — account IDs, ARNs, region-specific data — via Go template substitution. |

### How `family-e2e` Works

1. Reads `UPTEST_EXAMPLE_LIST` and extracts `apiVersion` groups from each manifest.
2. Determines which provider sub-packages are needed (e.g., `ec2`, `rds`, `config`).
3. Builds only those sub-packages (`make build-provider.$APIS`).
4. Deploys to a local Kind cluster (`make local-deploy.$APIS`).
5. Runs `make uptest`.

### Setup Script

The uptest target uses `cluster/test/setup.sh` as its `--setup-script`. This script:

- Creates `ProviderConfig` resources named `default` and `peer` from `UPTEST_CLOUD_CREDENTIALS`.
- Supports both cluster-scoped (`aws.m.upbound.io/v1beta1/ClusterProviderConfig`) and namespace-scoped (`aws.upbound.io/v1beta1/ProviderConfig`) variants.

### Uptest Invocation Details

```makefile
uptest: $(UPTEST) $(KUBECTL) $(CHAINSAW) $(CROSSPLANE_CLI)
    KUBECTL=$(KUBECTL) CHAINSAW=$(CHAINSAW) \
    CROSSPLANE_CLI=$(CROSSPLANE_CLI) \
    CROSSPLANE_NAMESPACE=$(CROSSPLANE_NAMESPACE) \
    $(UPTEST) e2e "${UPTEST_EXAMPLE_LIST}" \
      --data-source="${UPTEST_DATASOURCE_PATH}" \
      --setup-script=cluster/test/setup.sh \
      --default-conditions="Test"
```

## CI Pipeline

Defined in `.github/workflows/ci.yml`. Triggers on push to `main`/`release-*`, pull requests, and manual dispatch.

| Job | Runner | Purpose |
|-----|--------|---------|
| `detect-noop` | `ubuntu-latest` | Skips the pipeline if only docs/images changed (`.md`, `.png`, `.jpg`) |
| `report-breaking-changes` | `ubuntu-latest` | Runs `make crddiff` on changed CRDs + `make schema-version-diff` |
| `lint` | Large runner | `golangci-lint` v2.11.4 with `buildtagger` enabled |
| `check-diff` | Large runner | Verifies generated files match source; uploads `skipped_resources.csv` |
| `unit-tests` | Large runner | `make vendor vendor.check` → `make -j2 test` |
| `local-deploy` | `ubuntu-latest` | Builds provider, deploys to Kind, verifies it reaches `Healthy` |
| `check-examples` | `ubuntu-latest` | Validates example manifests against CRD schemas |

All jobs except `detect-noop` depend on `detect-noop` and are skipped when it reports no-op.

### Example Validation

```bash
./scripts/check-examples.py package/crds examples
```

The `check-examples` job runs `scripts/check-examples.py`, which validates that each example manifest in `examples/` has a matching CRD in `package/crds/` and checks YAML syntax, required fields, and API version correctness.

## Test Gaps

| Gap | Reason |
|-----|--------|
| No controller-level unit tests | All controllers are generated by Upjet — testing them would test the generator, not this repo |
| No mock AWS service tests | E2E against real AWS is the chosen strategy; no `localstack` or similar |
| Minimal unit coverage | Only config converters and client utilities have tests |
| `examples-generated/` not E2E tested by default | Auto-generated manifests may need manual fixup before they work in uptest |

The testing strategy is deliberate: since Upjet generates ~99% of the controller code, unit testing generated code provides low value. E2E tests against real AWS validate the full stack — Terraform provider, Upjet runtime, and Crossplane reconciliation — in a way unit tests cannot.
